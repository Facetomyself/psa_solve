## 2. 生产线（ruyijs 主线）

- 入口：`python scripts/demo6.py --solver ruyijs`（默认）；实现 `runtime/solve_ruyijs.py`（子进程隔离；venv `D:\reverse_ENV\temp\ruyijs-test-env`，ruyijs inner 0.2.2）。
- 形态：ruyijs 每 IP 窗口解一次锁 → 导出 `cf_clearance/__cf_bm` → curl_cffi(firefox impersonate) 批量采集。
- 已知缺陷：ruyijs 0.2.2 document 切换竞态（advance 抛 JSError、context 存活）——调用方容错继续泵即可；缺陷报告 `docs/ruyijs-0.2.2-document-swap-race.md`。

## 3. Node 桥定性（为什么不收敛）

三层证据链（全部同字节/同材料消变体，材料 `diagnostics/atob-diff-20261107/online-probe-new`）：

1. **JS 执行同构**：同材料下 ruyijs 生成的 FO r1 URL 与 Node **逐字节相同**（268 字符）；`put_resource` 注入 Node 的 FO 响应（229,968B）后两侧消费同一份字节；atob 前 825 调用逐字节相同、0 输出差。三份变体材料的 VM switch 循环逐 opcode 对齐（id 6/7 逐条一致；optrace3 八循环前缀完全一致）。
2. **分歧层**：FO r1 之后的第二层解码。第一层 atob（229,968→172,476）两侧一致；第二层 ruyijs →129,356 一次完成，Node 历史上 →72,697 反向收缩（不同变体下 Node 也能产出 Uint8Array(129,357) 但挂死在后续流处理）。
3. **失败点**：旧材料表现为调用方 f8 的无界自旋——`__lc[15]` 12,090,925 = 7×1,727,275 次 IW 调用；f8 探针实测**进入 4 次、退出 3 次**（前 3 次在 n=14/35 处 NaN 早退，第 4 次不退），`yz` 全程长度 0（全量计数 2,866,186 轮无一次非空），`yV` 固定 6-dispatch 周期（14:200:96:10:246 = 2:1:1:1:1），`m.state/h/j` 持续推进而 `m.v=NaN` 恒定。ruyijs 同函数进入 183 次、退出 183 次（181 NaN + 2 done），从不自旋。

**定性**：不是慢、不是不稳定，是**确定性死循环**——VM 码流由宿主面读数键控，Node mock 宿主的某个值级读数与 Firefox 不同 → 解码走错分支 → 程序静默进入重试路径（无异常无日志）。浅层缺口（performance 条目表、PerformanceObserver）已修复（前缀 759→825），剩余分歧在值/时序粒度且无 ground truth，补环境路线 ROI 已尽。共同不变量：失败点随变体轮换（12M 自旋 → Lpb 流处理 → 栈 `_0xd76b→…`），不变的是"键控解码守卫被触发"。

## 4. VM 分析成果（语义级，产物 `diagnostics/atob-diff-20261107/jsvmp-id15/`）

- **变体轮换实锤**：orchestrate 每请求返回不同加密变体（624,426/646,373/621,550B；同 idx 同长常量 20.3% 字节不同；解密器每变体换名换种子）。**跨会话材料不可混用**；对拍必须消变体。
- **id15 微程序**（web-jsvmp `chaos-vm-instrument`，回执 `collection-accepted`）：`IW` 内 **6 项 opcode 表（KU[3]：2176\|2181\|2177\|2183\|2180\|2182）+ 越界 undefined 终止符**的直线微程序；"表长 5"是 KU 寄存器数组长度。每次调用恰好 7 派发（SU=0..5 六步全 continue，SU=6 越界 break→return），377/377 严格成立。语义：2176 绑定 buffer/reader；2181 取数字 salt；2177 算 KU0/IV 并 `m.read(...)`；2183 折叠第二字节；2180 写 reader 游标；2182 混合/默认 pY 写 m.H。详见 `jsvmp-id15/bounded-semantics-id15.md`。
- **字符串隐藏器 b0**（atob + rolling 16-bit XOR）：可完全静态解码——每脚本 3,000+ 字面量、65 字符 alphabet 等均可离线还原（`static-payload-verify/extract.py`）。

## 5. 静态 payload 组装链（进行中）

FO r1 请求体结构已定位（`static-payload-verify/`，未执行 orchestrate 的纯静态 + hook 验证）：

```
明文对象 MZ（24 键，JSON 2,360B，哈希键名）
   → v0 内部加密（状态机 switch(Ms) + MD 微操作 + 常量函数 @415415 + c1/c0 填充）
   → 密文缓冲 M9（2,361B，熵 7.932，全字节域）
   → 3 bytes→4 symbols 自定义 base64（65 字符表 OY，输出 3,148B）
   → XHR.send（调用链 VM case DG('3262') → Seb → v0(Me[0]) → XHR.send）
```

- **alphabet 可静态提取**：每脚本唯一 65 字符全排列，经 b0 解码获得（online-probe-new @410299）。
- **CfReverse 配方（LZString `_compress(6)`）不适用**：912 种解包变体全败、first-symbol oracle 未命中——body 不是 LZ 输出（负结果已归档，避免重复投入）。
- **v0 是普通 JS 函数而非 VM 指令**——**已隔离为离线加密器（R1 完成，`static-payload-verify/offline-v0/`）**：P1 运行时回放三次字节级相等；P2 把 v0 的 56 个自由变量按四级处理（数据 JSON / 函数 src eval / 加载期工厂拼接 / 闭包键行为等价 XOR wrapper），`offline_v0.mjs` + `offline_data.json` 在纯 Node 零网络下复现 call1 3,148B 与 call2 7,042B（sha16 相等、first_diff=-1）。注意：D 类闭包键经"真实调用对"验证（6 次调用 XOR 流一致），跨变体是否稳定未验证——新变体需按重跑纪律重新捕获。
- **5,260B body（challenges.cloudflare.com /fo/）不属于 orchestrate**：生成器在 turnstile widget 自有脚本（api.js + rch iframe），独立 alphabet 实例；离线 400 是回放副产物（在线同位 200）。需覆盖时另抓其脚本。

**R2 完成（2026-11-07，`static-payload-verify/mz-fields/`）**：MZ 来源模板化通过。call1 24 键分类——页面材料 7（各变体匹配各自 `_cf_chl_opt`）+ 画像/固定 5 + 代码常量 3（token25，明文在 orchestrate）+ bool 3 + 运行态计数 4 + 派生未知 2；**零链式依赖**（FO 响应字节零匹配，MZ 纯由页面+脚本+运行态构成）；覆盖 91.7% ≥ 90%。跨 3 变体验证：键名哈希完全轮换（两两重叠 0）但 24 位置同型同构、角色多重集相等——**跨变体对齐按值形态/角色，不按键名**。call2 = call1 24 键（drop 1 bool）+ 28 undefined 哨兵 + 10 实质键（含 4 个高熵编码串 str43/268/334/MISS token25）。剩余缺口：token25 对（派生未知）与 call2 高熵串——若服务端校验这些值需运行时捕获或进一步溯源。参数化探针 `make_probe_mz.py`/`hook_variant_mz.py` 可复用于新变体。

**E2E 端到端验收（2026-11-08，`static-payload-verify/e2e-r1-body/`）**：builder 从（403 页 + orchestrate b0 解码 + 固定模板）构造 24 键 MZ——18 键纯静态（token25 3/3 静态搜出：2 个 obj1 模板字面量 + 1 个 odb 查表反查）+ 6 键运行时借用。**双变体（probe-new/optrace）组装 MZ vs dump 均 24/24 字节级相等**；built MZ 喂 offline_v0 → **3,148B sha16 `6a99b77dca045d4f` 与真实捕获 equal:true**。optrace 映射定位升级为「chl 字段名命中打分」+ 别名三形态泛化。borrowed 6 键 = 最小运行时集（4 计数/计时：perf 差/Date/state 计数 + 2 派生未知）。

**R2a 运行时键溯源（2026-11-08，`mz-fields/r2a-runtime/`）**：4 计数器 = **Date.now() 里程碑差**（B==C 全 dump 恒成立、漂移=机器负载、call2-D=call1-D+FO 往返 899~1024ms）；token25-top = VM 按材料确定性派生 id（0 赋值点）；err-msg = VM 错误记录 id（`new Error(hex24)` 站点定位）；call2 三高熵串 = **MG collector-dict（VM case qb，M6[2] 寄存器）标准 b64url 产物**、非 v0 alphabet、同材料确定性。终判：7 可模板化 + 3 仍需运行时（collector 串）；**call1 语义覆盖 24/24**；模板结构约束 D≥B、call2-D>call1-D。

**R2b 新变体可复制性验收（2026-11-08，`static-payload-verify/e2e-optrace/`）**：optrace 全流程演练通过——单次 ruyijs 捕获（60.6s）→ v0 四级法抽取（0.06s）→ builder 组装（~1s，**复制未改直接通过**）→ body 字节级全等（验证 A/B 双 PASS）。v0 定位：入口 XI@435814、状态机 ssb@488170。**最值钱发现：D 类闭包键 XOR key 材料无关**（optrace `_f3f278c7cdcae397f5a995d8` 与 probe-new `_123db518d8dbc065ca923f97` 是同一 bare global，16B key sha16 相同）——wrapper 跨变体复用，新变体可免 Mn 流捕获。**新变体接入成本 ~62s**。

**R2c collector 串终局（2026-11-08，`mz-fields/r2c-collector/`）**：beacon VM（9 opcode）解剖完成——**MG payload 槽所有静态调用点均传 undefined：beacon 与 payload 是同一批运行时命名槽的两个消费方**；call2 富集发生在 FO 响应处理 VM 内（W4 解码 230KB→129KB）。边界实验：同材料全同；同页换 FO → s43 不变、s268/s334 变；跨页全变；**捕获值禁跨页复用**。终判：s43 可模板化（页加载常量）；s268/s334 生成链已定位（FO 响应 VM），严格重生成需 R3 级语义恢复（判定可选）。**MZ 语义终态：call1 24/24 + call2 62/62；59/62 无捕获可构；每材料一捕即全闭环**。

**一键流水线（2026-11-08，`static-payload-verify/pipeline/`）**：`build_fo_body.py <material_dir>` 五级一键（S1 探针/S2 捕获/S3 v0 抽取/S4 builder/S5 终验），**本地全部三份变体材料全过**——body 逐字节相等（probe-new `45c3a4e79f1e39bf` / optrace `b1f04a5b7bbb9f5d` / optrace3 `612034926b6d3845`）；`--skip-capture` 复跑 ~1.2s。**D 类键三形态定位器**：①`NAME=CONV(NAME)` bare global（probe-new/optrace）②同族（XOR key 三材料全同）③`(CONSTS,FUNC)(HEX25,ARG)` 参数式（optrace3，FUNC 已声明普通函数、HEX25 参数全文唯一）。E 类静态修复（属性表捕获 vs 唯一静态定义冲突）。回归两旧材料无破坏。规律：变体形态空间 > 固定定位器，README 已知改写点手册是正确形态。
