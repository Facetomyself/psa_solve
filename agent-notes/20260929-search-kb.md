- **实际说了什么**: Firefox 151 ruyitrace 整理的 managed（`cFPWv=g`，`cType=managed`）`/fo` 管线。完成门是主站 accepted（约 3440 HTML + Set-Cookie clearance）之后，orchestrate **自己** `createElement(form)` + 3 hidden + `HTMLFormElement.submit()`，再同会话 POST 业务；明确写 `cf_clearance` 与 `location.reload()` **都不是完成**。失败码含 `E_RUNTIME_NO_FORM_POST`（有 cookie、无 form submit）。预置假 `window.turnstile` 可导致 accepted 后不进 form.submit。Form 节写明：accepted XHR 读完后几乎立刻进 DOM 提交，不是 Python 后处理。

## 对当前卡点的可迁移结论（来自命中文，非新推断）

1. 按归档口径，卡点阶段应标为 **accepted/clearance 之后、form.submit 之前**，完成门仍是 3 hidden 的证书 POST，不是 cookie 出现。
2. 优先对照 v2 文：accepted 回灌后是否自然建 form；假 Turnstile、只 reload、子站 accepted 误判主站等已知会卡住 form 的路径。
3. 壳版本/UA/h3 错配在知识库 **无直接归档答案**；需靠本项目 runtime 证据，不能从文章推出「h3 导致 forms=0」。
